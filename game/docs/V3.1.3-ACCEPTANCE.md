# V3.1.3 Acceptance — 事件一结局连续性热修复

> 日期：2026-08-10 | 状态：已发布至正式站点，常规公网验收与旧隐藏结局专项验收通过

## 发布目标

V3.1.3 修复事件一组织结局和共享隐藏结局被错误视为最终终点的问题，使所有事件一结局按“组织结局 → 可选共享隐藏结局 → 事件一片尾 → 事件二”连续推进，并让已经停在旧版共享隐藏结局的存档无需重玩即可恢复。

## 根因与修复

| 根因 | 修复结果 |
|------|----------|
| 结局舞台只允许 `credits-first-season` 继续，其余结局统一返回标题 | schema4 且仍有后续节点的结局统一显示“继续片尾” |
| 二至六组结局路由让共享隐藏结局抢在组织结局之前 | 路由先结算组织结局，再进入统一特殊结局网关 |
| 共享隐藏结局没有后续节点 | “崩坏、提线木偶、收束、发散”全部汇入事件一片尾 |
| 旧隐藏结局存档没有登记被跳过的组织结局 | 根据旧存档保留的路线、标记与最终数值重新解析并补齐组织结局副作用 |
| 三、五、六组部分隐藏组织结局被共享结局永久遮蔽 | “棋手、狂花、秘境、第七席、混乱纪元”恢复可达 |

## 兼容与迁移

- 保持 v4/v5 schema、所有 localStorage 键和手动存档格式不变，不执行批量迁移。
- 旧存档只在继续共享隐藏结局或提取事件二来源时按现有状态补齐原本应达成的组织结局、结局 CG 与连续性摘要。
- 已达成的“提线木偶”等隐藏结局不会被删除或改写；恢复后的收藏同时保留组织结局与共享隐藏结局。
- 新存档按修正后的顺序自然写入两个结局，不需要兼容分支。
