# 《4945区》2.5 Sol 方案：第二季后果与中点转折

> 状态：Sol 方案完成；具体中点事件依赖已冻结 canon 和 2.4 分支状态。
>
> 发布性质：回收前期选择并改变本季理解的中点剧情单元。
>
> 前置：[2.4 首次实质分歧](./SOL-PLAN-2.4.md)。
>
> 后继：[2.6 组织与关系压力交汇](./SOL-PLAN-2.6.md)。

## 1. 目标与范围

2.5 让 2.3–2.4 的选择真正产生代价，并在本集完成一个中点转折：玩家对主冲突、目标、盟友或自身位置的理解发生经 canon 支持的变化，后半季不能再按原计划简单继续。

中点不是“数值更高、敌人更强”的机械升级，也不是突然加入未铺垫的新事实。它必须由前半季行动和已确认公共压力共同推动。

## 2. 剧情单元合同

### 2.1 后果到达

- 每条活跃路线至少回收一个 2.3 或 2.4 登记的选择；
- 回收结果必须在场景、可用选项、关系反应、资源或路线状态中可见；
- fallback 玩家仍能完成本集，但不能获得不存在的前置成果；
- 不以一段总结文字替代所有后果演出。

### 2.2 中点转折

每条路线共享同一 canon 中点事实或压力，但通过各自处境体现不同代价。中点必须：

1. 回答前半季一个核心问题；
2. 揭示或确认一个足以改变行动方向的信息/结果；
3. 迫使玩家重新排序优先事项；
4. 形成后半季可执行的新目标；
5. 不提前解决最终危机。

### 2.3 本集收束

集末关闭“前期选择是否产生后果”和“玩家下一步要做什么”两个问题。可以保留局势恶化，但不能停在信息揭示后一帧而不给玩家回应。

## 3. 后果审计

payoff ledger 在本版增加以下检查：

- `dueIn = 2.5` 的每项均有消费节点和自动测试；
- 一个选择若有多个 routeScope，每个合法 scope 都有结果或明确共用 fallback；
- 已回收项标记实际 payoff，不因后续文字修订重复触发；
- 延期项必须经剧情审查并改写目标版本与原因；
- 不再使用的状态从后续消费合同移除，但保留旧 ID/tombstone。

## 4. 存档与内容修订加固

2.5 针对真实 episodic 更新补齐恢复能力：

- 从 2.2、2.3、2.4 任一完成点升级到 2.5；
- 在 2.4 分支中途保存、升级和继续；
- 已发布节点发生结构修正时通过 alias/tombstone 落到安全节点；
- `contentRevision` 迁移不改变 `schemaVersion`；
- 重复运行内容修订迁移保持幂等；
- 无法继续的存档隔离报错并保留原数据，不静默新建。

## 6. 验收标准

1. 每条活跃路线至少回收一个前期选择，结果在可玩内容中可观察。
2. 中点由既有因果推动，改变后半季目标，不依赖突然出现的未确认事实。
3. 玩家在中点后有一次回应或决策，本集具有完整阶段收束。
4. 所有 `dueIn = 2.5` 项关闭或有经批准的延期记录，测试 ID 可追溯。
5. 2.2–2.4 各完成点和 2.4 分支中途档均可升级继续。
6. schemaVersion/contentRevision 分离，alias/tombstone 和损坏档路径通过。
7. 第一季与全部已发布第二季 episode 零回归，本版素材全部 ready。
8. 类型检查、单测、内容图、构建、E2E、离线与目标设备验收通过。

## 7. 迁移与回滚

本版继续使用 schema5。回滚到 2.4 时，2.5 节点不能被旧内容图解析，客户端必须保留数据并要求升级；不能把中点后的状态猜回某个 2.4 分支。再次升级后原状态恢复。

## 8. 兼容性妥协

- 并非所有前期选择都在中点回收；未到期项可以留到 2.6–2.9，但必须在总账中有目标。
- 为保持旧存档可达，结构修正可能保留不再进入的新旧节点 alias。

## 9. 有意不做

- 不提前进入 2.7 最终危机或 2.8 高潮。
- 不用新 schema 掩盖内容迁移问题。
- 不重写已经发布的选择含义。
- 不生成图片或在提示词中补写 canon 外事实。

## 10. 退出闸门

中点因果、到期选择回收、跨内容修订恢复和正式素材全部通过后，2.5 才可发布。任何无法迁移的合法旧档都是阻断项。
