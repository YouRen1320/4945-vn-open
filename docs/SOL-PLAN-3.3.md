# 《4945区》3.3 Sol 方案：第三季多季余波落地与新目标

> 状态：条件 Sol 方案；具体场景依赖 3.2 canon 与序章终点。
>
> 发布性质：第三季序章后第一个完整剧情单元。
>
> 前置：[3.2 第三季共通序章与连续性开局](./SOL-PLAN-3.2.md)。
>
> 后继：[3.4 首次不可逆承诺与路线分歧](./SOL-PLAN-3.4.md)。

## 1. 目标与范围

3.3 把序章提出的问题转化为实际行动，让玩家看见前两季 durable outcomes 如何改变当前可用资源、人物态度或进入方式，同时建立第三季真正独立的新目标。

旧结果只能改变“如何面对当前问题”，不能替代第三季自己的冲突。所有第三季活跃路线在同一时间窗口内推进，不按路线排队开发。

## 2. 剧情单元合同

### 2.1 共通主干

- 从序章完成状态进入，不重复多季回顾；
- 执行序章形成的第一个行动目标；
- 展示至少一个 continuity fact 的可见影响；
- 揭示第三季局势中的竞争优先事项；
- 玩家作出应对选择并立即看到局部结果；
- 收束本次行动，形成 3.4 不可逆承诺的清晰压力。

### 2.2 路线同期变体

每条活跃路线必须拥有进入理由、人物立场、行动代价和合法出口。`acknowledged` 或 `retired` 的旧路线通过受控 scene/flavor 说明连续性，不重新膨胀为未经批准的结构路线。

### 2.3 Continuity 消费

- 每个 normalized fact 有消费节点、影响级别和 fallback；
- 不读取第一/第二季原始存档；
- 未消费字段从第三季白名单移除；
- 同一事实不能在多个路线复制成互相冲突的公共事件；
- 旧结果只能提供上下文、能力或代价，不能自动决定本集选择。

## 3. Episode 包与按季离线管理

3.3 完成三季规模下的资源管理：

- episode 内容包拥有 release、hash、节点和素材清单；
- 设置中按季显示预计体积、缓存版本和完整性；
- 玩家显式下载、更新或删除某季资源；
- 配额不足时提示，不静默删除其他季；
- 删除资源不删除存档、outcomes、收藏或设置；
- 当前 episode 与共享 UI 资源在更新中保持完整旧包，成功后原子切换。

## 5. 验收标准

1. 共通主干关闭序章行动目标，并建立第三季独立的新目标。
2. 所有活跃路线有同期可玩变体，无路线留待以后补做。
3. 至少一个 continuity fact 产生可见但受控的差异，又不代替玩家选择。
4. 每个 normalized fact 有消费或移除决定，非法 profile 使用明确 fallback。
5. episode/season 包的下载、更新、删除、配额不足、断网和回滚通过。
6. 删除季资源不影响存档、outcome archive、收藏或其他季。
7. 事件三序章与前两季完整回归，本版素材全部 ready。
8. 类型检查、单测、内容图、构建、E2E、离线和设备验收通过。

## 6. 迁移与回滚

本版沿用 schema5，只追加 episode 与内容修订。回滚到 3.2 时，未知 3.3 节点保留并提示升级或使用登记安全落点；资源包回滚必须恢复完整旧 hash，不混用新旧文件。

## 7. 兼容性妥协

- 按季离线改为玩家选择，未下载的季不承诺断网可玩。
- 退休路线只获连续性承认，不重新成为完整路线。
- 部分 flavor 组合共享场景，以避免低价值复制。

## 8. 有意不做

- 不提前实现 3.4 的不可逆分歧或后续危机。
- 不新增 canon 外角色、路线或事实。
- 不自动下载三季全部图片，不静默清理玩家缓存。
- 不生成图片或让 fallback 冒充正式素材。

## 9. 退出闸门

所有活跃路线完成同一时间窗口，continuity 消费、离线季包、正式素材和回归通过后 3.3 才可发布。
