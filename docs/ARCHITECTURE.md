# 技术架构

## 选型结论

采用 Vue 组件层 + 纯 TypeScript 场景图引擎 + Pinia 会话状态。第三方视觉小说脚本引擎没有引入：当前剧情需要职位权限、有限信息、组织状态和动态结局，使用强类型场景图更容易做一致性验证。

## 目录职责

```text
game/
  public/assets/       构建时直接发布的背景、头像和音频衍生资源
  src/components/      视觉小说舞台和通用面板
  src/content/         人物、组织、章节和剧情节点
  src/engine/          场景图、条件、效果、存档与校验
  src/stores/          当前会话、设置与收集状态
  src/styles/          设计令牌、布局和动效
  tests/               图完整性、历史路径和组件测试
```

## 场景图

每个节点具有稳定 ID、日期、幕、背景、呈现模式、发言者、文本、下一节点或选择列表。选择由三个部分组成：可见条件、状态效果、下一个节点。动态结局只读取已登记状态，不直接修改历史事实。

剧情函数不直接操作 DOM；引擎状态可在单元测试中无界面运行。所有 Vue 组件只负责呈现、输入和可访问性。

## 存档

- 存档模式：自动存档、快速存档、6 个手动槽。
- 存储：浏览器 `localStorage`，数据体积仅包含文本状态和节点 ID，不保存图片二进制。
- 每份存档包含 schema 版本、应用版本、时间、截图元数据、玩家状态、历史和收集信息。
- 导入时校验 JSON 结构与版本；迁移失败不覆盖现有存档。

## 发布与回滚

- 本地 `npm run build` 生成静态 `dist`。
- 上传到 `/srv/4945-vn/releases/<版本>`。
- 校验后原子切换 `/srv/4945-vn/current`。
- Nginx 只服务 `current`；回滚仅需把软链接指向上一版本并安全重载。
