# 事件三最终季合同（4.0.0）

## 完整范围

事件三从 `2027-01-04` 推进到 `2027-06-30`，共八个 episode：

1. 北岸来客（共通序章）
2. 七十二小时
3. 第一次承诺
4. 旧账中点
5. 信任重排
6. 最终立场
7. 北岸表决
8. 六月三十日

五条活跃路线 `org2`–`org6` 同期完成；`org1` 只作为公共历史与调解背景，不扩成第六条结构路线。

## 选择回收

| 状态 | 写入 | 主要回收点 |
| --- | --- | --- |
| `s3OpeningResponse` | 序章 | 七十二小时入口 |
| `s3RouteMethod` / `s3RouteArtifact` | 七十二小时 | 路线事故事实与后续责任语境 |
| `s3Commitment` | 七十二小时 | 第一次承诺、最终立场 |
| `s3Pledge` | 第一次承诺 | 旧账中点的实际事故后果 |
| `s3MidpointGoal` | 旧账中点 | 后半季行动语境与总结 |
| `s3RelationshipPromise` | 信任重排 | 六月三十日关系收束 |
| `s3FinalStance` | 最终立场 | 北岸表决可用行动与开场筹码 |
| `s3MainEnding` | 北岸表决 | 路线余波与不可变结果档案 |

已发布的序章存档缺少新字段时，只在真正需要该字段的入口提供明确补记；不从数值、路线或伴侣状态猜测。非法路线、未确认终局和缺少主要结局的状态进入隔离终点，不标记章节或季完成。

## 结局合同

- 五条路线各两个主结局：自治代价 / 保护条款，共十个。
- 全路线统一结局：`s3-ending-third-way`。
- 完整失败结局：`s3-ending-absorbed`，包含可玩余波，不显示“失败请重试”。
- 季终标记：`s3-finale-complete`。
- 关系收束：`together` / `apart-understood` / `broken` / `none`。
- 主要结局只由第三季结构选择决定；关系状态不能替换主要结局。

## 存储与归档

- 事件三进度：`4945-vn:s3:save:*`，沿用 schema5 基础结构。
- 事件三结局档案：`4945-vn:v1:s3-outcomes`，按内容摘要去重、不可变。
- 第三季档案保存事件二来源 ID、lineage、主要结局、关系收束和关键承诺。
- 删除普通事件三进度不删除第三季结局档案。
- 不改写事件一、事件二存档和既有事件二 outcome archive。

## 验收矩阵

- 5 路线 × 4 序章回应均能进入七十二小时并看见对应入口。
- 10 路线主结局 + 第三道路 + 失败结局全部可达。
- 12 合法伴侣 + 瓶/真理兼容关系 + none 均有季终场景。
- 线上 3.3.0 序章完成档可直接进入 `s3-72h-entry`。
- 全局剧情图无重复、断链、孤儿或意外终点。

## 兼容性妥协

- 继续使用 schema5，避免为了事件三单独迁移前两季存档。
- 低影响的伴侣差异共享公共关系选择与结局结构，但本人开场和本人季终场景保持独立。
- 第三季结果使用新的独立 archive 键，没有修改既有事件二档案结构。
