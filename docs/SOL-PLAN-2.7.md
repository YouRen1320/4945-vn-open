# 《4945区》2.7 Sol 方案：第二季后期危机与终局前置

> 状态：Sol 方案完成；具体危机必须来自已签认 canon 和 2.3–2.6 的累积因果。
>
> 发布性质：完整可玩的危机单元，不再是隔离垂直切片预览。
>
> 前置：[2.6 组织与关系压力交汇](./SOL-PLAN-2.6.md)。
>
> 后继：[2.8 高潮、失败状态与主要结局](./SOL-PLAN-2.8.md)。

## 1. 目标与范围

2.7 把前半季选择、路线分歧、中点变化和人物压力汇入后期危机。玩家必须在本集完成一次明确承诺或止损决策，确定自己将以什么状态进入终局。

危机不能靠突然加入一个未铺垫的强敌或事实制造。它必须能够从已发布 episode 的选择和公共压力中追溯；不同路线可以承受不同损失，但都要抵达可进入 2.8 高潮的合法终局入口。

## 2. 剧情单元合同

### 2.1 危机形成

- 至少一个 2.5/2.6 登记的后果到期并推动危机；
- 共通危机事实只维护一份，路线差异体现在暴露方式、承担者和可用应对；
- 玩家在行动前能理解风险、已有资源和可能失去的内容；
- 失败风险通过剧情和状态可见，不用隐藏阈值突然惩罚。

### 2.2 路线承诺

每条活跃路线必须完成：

1. 面对该路线最核心的组织或成员矛盾；
2. 消费至少一个前期路线状态；
3. 让玩家选择继续、改变策略、牺牲局部目标或退出某项承诺；
4. 展示即时收益与损失；
5. 生成明确的 finale entry state。

### 2.3 阶段收束

本集回答“危机发生后，玩家决定以什么立场进入终局”。可以把最终结果留给 2.8，但不能停在危机刚出现、玩家尚未行动的位置。

## 3. 终局入口合同

每个入口登记：

```text
finaleEntryId
route
requiredEpisodeCompletions
resolvedChoiceIds
openChoiceIds
availableResources
relationshipStateClass
failureWarnings
fallback
```

要求：

- 不直接读取任意 flags；
- 所有字段来自 episode 状态、摘要白名单或 payoff ledger；
- 每个合法 2.7 完成状态恰好映射到一个终局入口；
- 非法或损坏组合隔离报错，不静默分配“默认好结局”；
- 入口本身不判定最终结局，2.8 使用显式结局规则计算。

## 4. 终局前内容审计

进入 2.8 前必须完成：

- 所有活跃路线从 2.2 到 2.7 的时间窗口连续；
- 所有 structural 分支有终局入口、合流说明或批准关闭记录；
- `dueIn <= 2.7` 的选择全部回收；
- 尚未回收的选择明确属于主结局、尾声或关系收束；
- 每个主要失败状态有铺垫和可理解预警；
- canon 中没有仍影响高潮但尚未决策的 P0/P1 空位。

## 6. 验收标准

1. 危机由已发布因果推动，无未经确认的突发事实。
2. 每条活跃路线都有可玩的危机应对、玩家承诺、即时代价和终局入口。
3. 所有合法完成状态恰好映射到一个 finale entry state；损坏状态不被静默纠正。
4. 失败风险有可理解预警，但本版不提前判定最终结局。
5. `dueIn <= 2.7` 的选择总账清零，开放项均明确归属 2.8 或 2.9。
6. 从 2.2–2.6 任一合法旧档升级可到达本集；回滚保留状态。
7. 第一季与全部第二季前序 episode 零回归，本版素材全部 ready。
8. 类型检查、单测、内容图、构建、E2E、离线和目标设备验收通过。

## 7. 迁移与回滚

本版不升级 schema。回滚到 2.6 时保留 finale entry 与危机状态，旧版本只允许在已登记的 2.6 安全点查看或提示升级，不能撤销玩家承诺。重新升级后继续原终局入口。

## 8. 兼容性妥协

- 为保证终局可测试，多个低影响 flavor 状态可能合并到同一 finale entry，但对应对白差异仍可保留。
- 失败预警提供风险类别而非精确数值，避免把叙事选择变成公式题。

## 9. 有意不做

- 不在本版交付最终高潮、主要结局或路线尾声。
- 不新增 canon 外的危机来源、角色或组织。
- 不允许 unresolved structural 分支带着“以后再说”进入 2.8。
- 不生成图片或把预结局画面混入本版清单。

## 10. 退出闸门

全部终局入口、选择回收、连续性、正式素材和回归通过后，2.7 才可发布。任何无入口的合法状态或无铺垫的失败条件都是阻断项。
