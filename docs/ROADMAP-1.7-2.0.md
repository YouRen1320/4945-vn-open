## 6. 跨版本规则

1. 2.1–2.9 每版必须有开端、冲突、有效选择、后果和阶段收束，不能只发布架构或“待续”节点。
2. 第二季不按路线逐条做完；每版覆盖所有活跃路线的同期变体。
3. 第一季补遗使用 `s1x-`，第二季使用 `s2-`，第二季回望使用 `s2x-`，第三季使用 `s3-`；已发布 ID 只追加不改义。
4. schema 版本与剧情 `contentRevision` 分离。
5. 从 2.2 起使用 choice payoff ledger，延迟后果必须指定回收版本。
6. 季结果只通过不可变 outcome records 和白名单 continuity profile 进入后续季，不复制任意 flags 或完整历史。
7. 图片由用户使用外部模型生成；Sol 提供逐版提示词，稳定版要求本版托管视觉全部 ready。
8. 未经用户确认，不把 2026-07-28 后的具体事实写入正式场景。
9. 3.x 默认继续 schema5；不因进入 4.0 自动升级 schema6。
10. 三季素材按季选择离线下载，删除资源不删除存档、收藏或 outcome archive。

## 7. 明确非目标

- 不做账号、云存档、遥测、数据库、付费或多人实时功能；
- 不用节点数相等代替路线戏剧完整性；
- 不在 4.0 范围删除 v4/v5、旧收藏或 outcome records；
- 不假设 4.0 是作品永久完结；
- 不在本轮规划中生成图片或修改运行时代码。
