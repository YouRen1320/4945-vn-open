# 《4945区》视觉小说设计系统

> 本文件是界面与叙事表现的统一基线。页面级规则可在 `pages/` 中覆盖，但不得破坏“舞台优先、单一焦点、信息渐进披露”。

## 产品定位

- 类型：移动端优先的 Web Galgame / 群像视觉小说。
- 气质：传统日式视觉小说构图、半写实黑色幽默、克制的东方装饰。
- 核心体验：玩家先认识人，再承担决定；史实通过事件发生，不通过策划说明宣布。
- 非目标：管理后台、策略说明书、数值养成面板或多层卡片式 Web 应用。

## 叙事优先级

1. 当前说话者、具体动作与情绪。
2. 场景图片、人物立绘和剧中设备。
3. 玩家此刻能说或能做的事。
4. 系统控制与收藏信息。

历史类型、路线收益、好感变化、版本号和制作说明不得出现在默认游玩层。

## 单一焦点场景

- 普通剧情：背景/CG + 人物立绘 + 底部对话框；选择替换或紧贴对话框。
- 私聊/群聊：所有消息和回复都在剧中手机内；隐藏底部 Galgame 对话框。
- 游戏客户端：操作与反馈发生在客户端画面内；不叠加第二套选择卡。
- 事件 CG：CG、台词和最低限度控制栏；避免无关面板遮挡画面。
- 同一时刻只允许一套主要叙事界面。

## 标题页

- 主标题：`4945区`。
- 副标题：`影·银角 · 新区开服篇`。
- 只展示主菜单，不展示季号、剧情日期、版本号、同人说明或玩法宣言。
- “先上号再说”只作为剧中台词出现，不再同时充当作品名和人物名。
- 版本与制作信息移动到“设置 → 关于”。

## 建档与输入

- 开场只在聊天中询问游戏昵称；昵称必须真实进入对话、存档与状态。
- 第六组织名称仅在玩家选择创建第六组织后询问。
- 不提前询问无实际剧情作用的性别、现实身份或表达方式。
- 输入框高度至少 44px，标签可见，字数限制与错误显示在输入附近。

## 选择规则

- 普通场景默认 2–3 项；4–5 项只用于经过铺垫的重大路线选择。
- 选项写成第一人称台词或具体动作，避免治理术语、作者结论和策略摘要。
- 默认不显示数值、关系变化、未来结果或“最优解”说明。
- 去掉常规选择的 `01/02/03` 编号；差异通过措辞、人物反应和后续场景体现。
- 聊天回复使用消息气泡形态；普通剧情使用简洁的传统选择框。
- 选择后的第一拍必须出现可感知反馈：回复、表情、系统回执或场景变化。

## 文案规则

- 每个场景必须回答：谁想要什么、眼前阻碍是什么、玩家为什么现在要回应。
- 用可观察事件代替概括：消息、停顿、删除、上线、退群、截图、战报。
- 旁白以 1–3 句为主，避免提前总结人物、路线和历史意义。
- 黑色幽默来自言行反差，不由旁白直接解释笑点。
- 新角色首次出场至少拥有一句只属于他的说话方式。

## 史实与改编

- `confirmed / adapted / fictional` 元数据继续保留在剧本内部，供校验与资料档案使用。
- 默认游玩界面不显示“史实节点、改编桥段、虚构支线”。
- 固定历史节点直接发生；玩家通过所在位置、回应和后果感受到局部改写。

## 视觉语言

- 主色：酒红 `#b65f7f`，强调 `#d97e9f`，暖金 `#e6b681`。
- 夜色：`#1d141c` / `#30202d`；对白纸面使用暖白而非纯白。
- 标题使用宋体/明朝体气质，正文使用系统中文无衬线字体。
- 大图优先，面板尽量轻；模糊仅用于明确的前后层分离。
- 图标统一使用 Lucide 线性图标，不使用 Emoji 作为结构图标。

## 响应式与可访问性

- 以 375×812 竖屏为基准，同时验证 844×390 横屏和 1440×900 桌面。
- 触控目标至少 44×44px，间距至少 8px；输入文字在手机端不低于 16px。
- 尊重安全区、系统返回手势和 `prefers-reduced-motion`。
- 正文对比度至少 4.5:1，所有图标按钮必须有可读标签与键盘焦点。
- 选择列表不得横向溢出，不得遮住当前说话者的关键信息。

## 验收问题

- 玩家能否在五分钟内说出：谁联系了我、我为什么进区、下一步想看什么？
- 玩家是否在理解人物之前就被迫选择治理方案？若是，判定失败。
- 玩家看到的是自己会说的话，还是作者对后果的解释？后者判定失败。
- 任一截图若同时出现两套对话/选择系统，判定失败。
- 所有可见输入是否真实影响当前或后续剧情？否则删除或延后。
